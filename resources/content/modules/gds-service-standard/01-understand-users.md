## Introduction

Point 1 of the GDS Service Standard requires teams to understand users and their needs. As a solution architect, this shapes how you design systems that genuinely serve user requirements.

## User Research in Architecture

Architecture decisions should be informed by user research findings. Understanding user journeys helps architects design systems that support the right interactions at the right scale.

## Mapping User Needs to Technical Decisions

Each user need should trace to architectural decisions. Document these mappings to demonstrate alignment during service assessments.

---
keyTakeaways:
  - Architecture decisions must be traceable to user needs
  - Engage with user researchers to understand the full user journey
  - Document the link between user needs and technical choices

practicalExamples:
  - Create architecture decision records that reference specific user research findings
  - Map user journey stages to system components to identify performance-critical paths
